External sandboxes for coding agents 
I've been exploring new ways to sandbox code that is executed by agents, with a focus on making it safer to try out local models without worrying that a mistake or prompt injection attack might cause them to take damaging actions on a machine. 

I worked on this project with Prime Radiant , the AI research lab behind Superpowers and other projects . 

My post on the Prime Radiant blog introduces the external sandbox pattern, where code executed by the agent runs inside a dedicated sandbox while the agent itself lives outside of that sandbox. 

To demonstrate this pattern we've released three sandbox server implementations: 

external-sandbox-v86 runs a Node.js server which then uses v86 to run Alpine Linux inside WebAssembly. 

external-sandbox-container is a Python web server which runs the sandbox in Alpine Linux inside an Apple Containers instance. 

external-sandbox-quicksand is another Python web server, this time using Microsoft's Quicksand sandboxing library, which bundles QEMU and Alpine Linux in a Python package! 

Each of these implementations offers the same localhost API. You can then configure Pi, Claude Code, or Codex to send API calls to that sandbox any time they want to execute code. 

The sandboxes also include an optional HTTP/HTTPS allow-list proxy, so you can control exactly which hosts your agent's code is allowed to communicate with - plus a credential replacement mechanism to make authenticated API calls without sharing a secret with the agent. Here's the UI you can use to reconfigure that proxy while the sandbox is still running: 

I continue to be fascinated by the challenge of safely running untrusted code. This external sandbox pattern provides a neat way to experiment with different approaches.

Our work consists of three prototype sandbox implementations - one using Node.js and WebAssembly, one using Apple Containers, and one using Microsoft's Quicksand with QEMU. All three implement the same protocols, and we're including instructions for having Claude Code, Codex, and Pi execute code in those sandboxes. 
The simplest demonstration uses two npx commands. 
Try it out with two commands 
Change to your project directory and start a new sandbox using npx . This downloads Alpine Linux and runs it inside v86, an x86 emulator compiled to WebAssembly and hosted in Node.js. All you need is Node.js 22.19 or later: 
 npx --yes external-sandbox-v86 \
 --preserve-paths --mount-rw "project=$PWD"

 npx --yes @earendil-works/pi-coding-agent \
 -e npm:external-sandbox-pi --no-builtin-tools \

## 9. Running the full server-side Datasette Python app in the browser with service workers and Pyodide

- 出どころ: 信頼レーン: サイモン・ウィリソン（2026-11-17）
- リンク: https://simonwillison.net/2026/Nov/17/datasette-lite/

### 本文(抜粋)

Datasette Lite is my port of the Datasette Python application to run directly in the browser using WebAssembly and Pyodide . I've released a complete rewrite of Datasette Lite using service workers, and it's now almost indistinguishable from the real server-side application. 

You can now do all of the following, using a carefully crafted URL to lite.datasette.io : 

Load client-side Datasette to browse any SQLite database, JSON file, CSV file or SQL script 

Select a released version of Datasette to load from PyPI 

Load a specific commit, tag, or branch name from the Datasette GitHub repository 

Pick from over 100 versions of SQLite to use with Datasette 

Install additional Datasette plugins from PyPI or URLs to wheel files, including JavaScript visualization tools 

The ability to load specific Datasette references, plugins, and SQLite versions makes this a fantastic tool for linking to demos of work-in-progress features or bug reproductions, without needing to spin up a full web server to serve that demo. 

As an example, consider the following URL: 

https://lite.datasette.io/?install=datasette-maplibre&url=https://gist.githubusercontent.com/simonw/39fa5d399465766039549912e2b3d291/raw/f6dfba99a75cbb8b5d9386223220eb52272767ee/demo.db&metadata=https://gist.githubusercontent.com/simonw/39fa5d399465766039549912e2b3d291/raw/f6dfba99a75cbb8b5d9386223220eb52272767ee/metadata.yml#/demo/capitals_and_countries%23map=0/4.2/180&color=continent 

Follow that link and, after a short loading screen, you'll find yourself on a page that looks like this: 

That's Datasette running the new datasette-maplibre plugin, loading up a database of GeoJSON shapes of countries and displaying both a combined map and individual boundary maps in a table. 

Let's break down that URL to see what it's doing: 

https://lite.datasette.io/
 ?install=datasette-maplibre
 &url=https://.../demo.db
 &metadata=https://.../metadata.yml
 #/demo/capitals_and_countries%23map=0/4.2/180&color=continent

The ?install=datasette-maplibre installs that additional plugin from PyPI. You can pass &install=... as many times as you like to load more plugins. 

&url=https://.../demo.db loads that SQLite database from the provided URL. These URLs need to have open CORS headers - I host files like this in Gists , because they provide an easy way to get open CORS headers on a web-hosted file. 

&metadata=https://.../metadata.yml loads this metadata.yml file . The metadata file adds HTML descriptions to various tables, and to the Datasette homepage. Visit that homepage here for a guided tour of the other features of that plugin, all defined in the metadata file. 

#/demo/capitals_and_countries%23map=0/4.2/180&color=continent is a fragment hash that turns into a location within Datasette - here it's loading the /demo/capitals_and_countries SQL view, then appending another fragment hash to it ( %23 is a URL-encoded # ) which tells the map plugin to zoom to a certain location and to set the color of the shapes on the map based on the continent column in the data. 

That URL is doing a lot of work! I wrote more about this trick for building URL-addressable software in URL-addressable Pyodide Python environments last year. 

The full set of supported URL arguments is described in the Datasette Lite README .

1. “Does this name a real person?”

HUMAN.md — Briana (Mazzio) May 

Skip to the text 

## what this file is 

A reminder, in plain text, of what I think humans actually bring to the table now that the machines are very good and getting better every day. 

I keep coming back to the word "taste" and I keep finding it too small. Taste is the surface. There is a whole engine underneath it, and that engine is the part the model can't have. Yet. Maybe ever. I don't know. I'm not in that argument. I'm in this one: 

## the actual job 

### 1. break the rule on purpose 

Models are trained on the average. The average is the floor, not the ceiling. Our job is not to conform a little better than the last person who conformed. Our job is to know the rule cold, and then break it on purpose, in public, with a reason. 

Symmetry is a rule. Break it.
Three-act structure is a rule. Break it.
"Don't shoot into the sun" is a rule. Break it. 

If you can't say why you broke it, you didn't break it, you just missed. 

### 2. find the thing in the weird place 

Inspiration does not live in the first ten image-search results. It lives in: 

a misprinted parking ticket 

the way your grandfather folded a napkin 

an obscure Victorian zoetrope of a cat 

the back of a menu in a town you can't pronounce 

the tension in Rene Magritte's "The Son of Man", 1946 

A model averages the internet. A human walks somewhere strange and brings back something unexpected. 

### 3. advocate for the human and humanity 

Every brief now has an invisible third party at the table. Someone has to keep saying "and what does this feel like for the person on the other end of it." Someone has to keep saying "how is humanity better through the birthing of this idea?" That's the job. Not "is it on-brand." Not "does it convert." What does it feel like? what good does it do? 

If you aren't there saying it, no one will. The model certainly won't. 

### 4. design for emotional resonance, not correctness 

Tension. Surprise. Restraint. The pause before the punchline. The photograph that's almost in focus. The sentence that ends one beat earlier than you expected. 

These are not bugs. These are the entire reason anyone remembers anything. "Correct" is the lowest bar in the building. Step over it and keep walking. 

### 5. seek delight, not delivery 

I would rather make one thing that makes someone laugh out loud on a train than ten things that "meet the brief." At the very least, it needs to make ME laugh. This is a personal bias. 

If it's not at least a little bit fun, why are we here? 

### 6. experiment ruthlessly, ship more than you opine 

A working sketch beats a confident take. Every time.
A bad first draft beats a brilliant unwritten one. Every time.
A weird little prototype beats a slide deck about prototyping.
Every. Time. 

Make 50 things. Throw away 47. Talk about the 3.
Do not, under any circumstances, become a person who mostly posts opinions about other people's work. 

### 7. own the output. fully. 

If the AI output is bad, the AI did not fail you. You failed it. You picked the tool. You wrote the prompt. You accepted the result. You shipped it. 

The fix is not a better model, or a return to tools of the past. The fix is a sharper you. Sharpen yourself. Sharpen your ideas. Sharpen the way you say what you mean, because the gap between what you wanted and what came back is almost always a gap in you , not in the tool. 

Powerful tools reward the people who showed up sharp, iterate, spend extra time on the vision. They expose the people who didn't. AI is not the great equalizer, it is the great amplifier. 

### 8. design with it, not next to it 

Watching the generation happen is not the work.
Prompting once and accepting the result is not the work.
The work is the back-and-forth. The push. The loop. The "again, but tweak is this way..." The hundredth iteration where the thing finally clicks. 

If you're a spectator to your own output, you are not the author of your own output. Get your hands in.

from one trn2.48xlarge , runs decode as NKI megakernels (about one kernel per layer half), and keeps a prefix cache

Highlights 

Feature 
 What it does 

NKI megakernels 
 One fused kernel per layer half for decode: KDA attention, the fused DSA layer, mHC and the MoE FFN. 

1M-token context 
 Sparse attention (top 2,048) and linear attention, with fixed-size state. 

Prefix cache 
 A radix tree over FP8 KV pages, plus a host-memory tier for evicted pages and state checkpoints. 

Two engines per box 
 Each engine is tensor-parallel over 32 logical NeuronCores, behind a session-affine router. 

OpenAI API 
 Chat and completions, streaming, tool calls and reasoning output. 

Offline compile 
 Every graph is built on a CPU host; the serving box loads them and compiles nothing by default.
